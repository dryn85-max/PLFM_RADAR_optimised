# Spec: web console log page `/log` (ESP32 MVP)

Date: 2026-10-03. Owner: Andrii. Status: approved in brainstorming (2026-10-03).

## Context

The owner tests the stand on the balcony (GPS), far from the Mac with the USB console. The ESP32
can run from a power bank there; the log must be readable on a phone over Wi-Fi.

## Decisions (owner, brainstorming 2026-10-03)

1. A web page **`/log`** with the console log, readable from a phone (option A). No TCP log port
   (option B rejected for now), no log in the `.ldrec` recording.
2. Built in the same PR as the GPS UTC validity work (#10), so both are bench-checked together.
3. The page is served on the home network (STA) and on the AP (on demand or fallback), like the
   live page.
4. The AP password never reaches the web log (it stays on the USB console only).

## Requirements

### R1. Capture (core ring buffer host-tested; hook in esp32/main)
- Hook `esp_log_set_vprintf`: every ESP_LOGx line still goes to the USB console unchanged (call the
  previous vprintf) and is also appended to an in-memory text ring buffer of 16 KB (one constant).
- The ring buffer (core, C11, host-tested) stores bytes with a monotonically increasing 32-bit
  write offset; readers ask "from offset N" and get the bytes still held, plus a flag when N was
  already overwritten (gap) and the next offset. Wrap-safe offsets.
- ANSI colour escape sequences (`ESC [ ... m`) are removed before storing.
- Lines containing `AP password` are dropped (defence in depth: today that line is printed with
  printf, which the hook does not see).
- The hook never blocks: a short critical section for the copy; formatting into a bounded stack
  buffer (lines longer than it are truncated with a marker). Safe from any task; not used from ISRs
  (ESP_LOG is not ISR-safe anyway).

### R2. HTTP
- `GET /log`: an HTML page (same dark style as the live page; monospace, auto-scroll that pauses
  when the user scrolls up, buttons **Copy** (clipboard API, falling back to execCommand) and
  **Select all**, a status line with the byte count and a "lines lost" note on a gap). It polls
  `GET /log/data?from=N` once per second.
- `GET /log/data?from=N`: `text/plain` body with the bytes from N (at most ~4 KB per response,
  the client keeps polling), response headers `X-Log-Next: <offset>` and `X-Log-Gap: 0|1`. Without
  `from`, the whole buffer.
- Served on STA and AP. A link to `/log` from the live page footer and from `/wifi` and `/ld2410`.

### R3. Docs
- `esp32/README.md` (log page, what is and is not captured: printf output such as the boot banner
  and the AP password line is not in the web log), `docs/decisions.md` (decisions 1-4).

## Non-goals
No TCP/syslog, no persistence across reboots, no log levels control, no authentication.

## Acceptance
CI green; host tests pass; owner: on the phone `aeris-mvp.local/log` shows the live log incl.
the `gps:` lines, Copy works (or Select all + copy), the AP password line is absent.
