# Spec: OTA firmware update over Wi-Fi (ESP32 MVP)

Date: 2026-10-03. Owner: Andrii. Status: approved in brainstorming (2026-10-03).

## Context

Flashing needs the Mac and a USB cable at the stand; the stand moves (balcony). ESP-IDF supports
OTA updates with two app slots and bootloader rollback. Flash is 32 MB; the app is about 1 MB.

## Decisions (owner, brainstorming 2026-10-03)

1. Upload: **both** a page and a command line on one endpoint, **AP only**
   (`http://192.168.4.1/update`): the page uploads `aeris_mvp.bin` with progress; from the Mac
   `curl --data-binary @build/aeris_mvp.bin http://192.168.4.1/update`. Never from the home network.
2. A new image is marked valid only when **Wi-Fi is up (STA got IP or an AP runs), the HTTP server
   runs and 30 s have passed**. Agent addition (stated in brainstorming, not objected to): if that
   is not reached within **120 s**, the image marks itself invalid and reboots into the previous one.
3. `/update` shows the running version (app version = git hash), build date and time, running slot,
   the version in the other slot, and a **"Rollback to previous"** button.
4. Partition table (agent choice, stated in brainstorming): NVS unchanged (0x9000, 0x6000) so the
   Wi-Fi credentials and the AP password survive; `otadata`; two **4 MB** app slots; the rest of the
   flash unused. No secure boot / image signing (the AP-only upload is the protection).

## Requirements

### R1. Partitions and bootloader
- `esp32/partitions.csv`:
  `nvs,data,nvs,0x9000,0x6000` / `otadata,data,ota,0xf000,0x2000` /
  `phy_init,data,phy,0x11000,0x1000` / `ota_0,app,ota_0,0x20000,4M` / `ota_1,app,ota_1,,4M`.
- `sdkconfig.defaults`: custom partition table with that file, `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`.
  The `#error` guard in `app_main.c` changes to require the custom table and rollback.
- One-time migration by USB (`rm esp32/sdkconfig`, `idf.py flash`): bootloader, table, otadata and
  ota_0 are written; NVS is untouched.

### R2. Validity check (decision logic in core, host-tested)
- At boot, if the running image is `ESP_OTA_IMG_PENDING_VERIFY`: a 1 s timer evaluates
  (wifi_up, http_up, uptime) -> `NONE` / `MARK_VALID` (all true and uptime >= 30 s) /
  `ROLLBACK` (uptime >= 120 s without MARK_VALID). Constants in one place. Logged.
- Images not pending (first USB flash, already valid) are left alone.

### R3. `/update` (AP only; 404 from the STA side for every method)
- `GET /update`: page in the `/wifi` style: running version/date/time/slot, other slot version
  (or "empty"), the upload form (file input, Upload button, progress bar via XHR upload events,
  result), the Rollback button (only when the other slot holds a valid image; confirm()).
- `POST /update`: raw body = the `.bin` (no multipart); Content-Length required and <= slot size;
  `esp_ota_begin` on the next slot, streamed `esp_ota_write` in chunks from a heap buffer,
  `esp_ota_end` (image check), `esp_ota_set_boot_partition`, response "OK, rebooting", restart after
  about 1 s. One update at a time (concurrent request -> 409). Any error -> `esp_ota_abort`, error
  text, no reboot. Works with the page and with `curl --data-binary` (`Content-Type` ignored).
- `POST /update/rollback`: if the other slot holds a valid image, set it as boot partition and
  restart; otherwise 409.
- Links from `/wifi`, `/ld2410` and `/log`.

### R4. Docs
- `esp32/README.md` (migration steps, update from the page and with curl, what happens during an
  update: flash writes disturb frames and the recording, a GAP and a new boot_id in the recording;
  rollback rules), `docs/decisions.md` (decisions 1-4), BACKLOG (close the OTA item).

## Non-goals
No signing/secure boot, no update from the home network, no update of the bootloader or the
partition table over the air, no automatic download from a server.

## Acceptance
CI green; host tests pass; owner: USB migration keeps Wi-Fi settings; an update from the page and
one with curl boot the new version (`App version` changes) and it becomes valid after 30 s; the
Rollback button returns to the previous version; a deliberately broken image (e.g. a build that
never starts Wi-Fi) rolls back by itself after 120 s.
